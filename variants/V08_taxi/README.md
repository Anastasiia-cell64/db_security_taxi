# Варіант 08. Служба таксі

## Предметна область

Київська служба таксі. Клієнти замовляють поїздки через мобільний застосунок або телефоном через диспетчера. Водії — ФОП-партнери на власних авто; їхній застосунок постійно передає геолокацію, а під час поїздки пише GPS-трек. Служба підтримки розбирає скарги: загублені речі, завищену вартість, поведінку водія. Поїздки оплачуються готівкою, карткою або за корпоративним договором.

## Таблиці

| Таблиця | Призначення | Записів |
|---|---|---|
| `staff` | Диспетчери та підтримка; `db_login` — логін PostgreSQL | 6 |
| `drivers` | Водії — **персональні дані**, поточна геолокація; `db_login` — логін PostgreSQL | 40 |
| `vehicles` | Автомобілі (держномер, марка, клас) | 42 |
| `customers` | Клієнти — **персональні дані**, збережена адреса «Дім» з координатами | 180 |
| `trips` | Поїздки: хто, з ким, звідки, куди, коли, скільки коштувала | 450 |
| `trip_track_points` | GPS-трек поїздок (6 точок на поїздку) | ≈ 2 360 |
| `payments` | Оплати завершених поїздок | ≈ 390 |
| `support_tickets` | Звернення до підтримки | 60 |

## Чутливі дані

- `customers`: ім'я, прізвище, телефон, email — **ПД**; `home_address`, `home_lat`, `home_lon` — **особливо чутливі** (де людина живе)
- `drivers`: ПІБ, дата народження, телефон — **ПД**; `license_no`, `tax_id`, `iban` — **особливо чутливі**; `current_lat`/`current_lon` — де людина перебуває просто зараз
- `trips`: адреси й координати подачі та призначення — **геолокаційні дані**. Історія поїздок однієї людини розкриває, де вона живе, працює, лікується (див. «Олександрівська лікарня» в довіднику точок), з ким і коли буває. Саме тому координати вважаються одними з найнебезпечніших ПД
- `trip_track_points` — повний маршрут переміщення з точністю до хвилини
- `payments.card_last4`, `payments.payment_ref` — платіжні дані

**Кандидати на шифрування (етап 4):** `drivers.tax_id`, `drivers.iban`, `drivers.license_no`, `customers.home_address`, `payments.payment_ref`. Координати (`numeric`) теж можна шифрувати, але тоді доведеться перевести їх у `bytea` і втратити можливість рахувати відстані в SQL — подумайте, чи це виправдано.

## Ролі та їхні бізнес-задачі

| Роль | Що має робити | Логіни в `*.db_login` |
|---|---|---|
| диспетчер (`dispatcher`) | Приймає телефонні замовлення: шукає клієнта за телефоном або реєструє нового (ім'я + телефон), створює поїздку, призначає водія й авто (змінює `driver_id`, `vehicle_id`, `status`), скасовує замовлення. Для вибору водія бачить **поточну** геолокацію, статус і клас авто водіїв, але не їхні ІПН, IBAN, посвідчення, дату народження. Історичних GPS-треків, оплат і звернень не бачить. Адресу «Дім» клієнта не бачить — адресу подачі клієнт називає сам | `u_dispatcher1`, `u_dispatcher2` (у `staff`) |
| водій (`driver`) | Бачить **лише власні поїздки** і власний профіль та авто. Змінює статус своїх поїздок (`assigned` → `in_progress` → `completed`), час початку/завершення. Ім'я та телефон клієнта потрібні лише на час активної поїздки; після завершення — тільки адреси, відстань, вартість і оцінка. Даних інших водіїв, оплат клієнтів (крім суми й способу оплати власних поїздок) і звернень не бачить | `u_driver1` … `u_driver5` (у `drivers`) |
| підтримка (`support`) | Веде `support_tickets` (створює, бере в роботу, закриває). Для розбору скарги читає поїздки й оплати: суму, спосіб, статус — без `payment_ref`; може змінити `payments.status` на `refunded`. Телефон клієнта бачить маскованим, ІПН/IBAN водія — ні. Координати й GPS-трек бачить **лише в огрубленому вигляді** (округлення до ~1 км, відстань, тривалість, середня швидкість), без точних точок — цього достатньо, щоб перевірити «водій поїхав довшою дорогою» | `u_support1`, `u_support2` (у `staff`) |
| застосунок (`app`) | Сервісний обліковий запис бекенду мобільних застосунків: реєструє клієнтів, створює замовлення, записує точки треку і поточну геолокацію водіїв, створює оплати, приймає звернення від клієнтів. Нічого не видаляє; до ІПН/IBAN водіїв доступу не має | — (створюєте самі: `svc_mobile`) |

## Підказки до етапів

- **RLS (етап 3):** `trips.driver_id` + зіставлення `drivers.db_login = current_user`; так само для `trip_track_points` і `payments` (через `trip_id`). Водій у таблиці `drivers` має бачити лише свій рядок. Логіни диспетчерів і підтримки — у `staff.db_login`, на них RLS не обмежує рядки.
- **Маскування (етап 3):** представлення для підтримки з `round(pickup_lat, 2)` / `round(pickup_lon, 2)` замість точних координат і з маскованим телефоном `+38067*****12`; агрегати по треку замість точок.
- **Шифрування (етап 4):** `drivers.tax_id`, `drivers.iban`, `drivers.license_no`, `customers.home_address`, `payments.payment_ref`.

## Розгортання

```bash
docker compose exec db psql -U postgres -c "CREATE DATABASE taxi"
docker compose exec db psql -U postgres -d taxi -f /variants/V08_taxi/schema.sql
docker compose exec db psql -U postgres -d taxi -f /variants/V08_taxi/seed.sql
```

Усі дані синтетичні; збіги з реальними людьми випадкові. Координати — реальні точки Києва та випадкові точки в межах міста.
